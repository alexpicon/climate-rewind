## Code changes (all in `pipeline/`, uncommitted)

- `detective.py`
  - **Bug fix: thinking blocks.** The model returns `thinking` blocks, and `_block_dict` sent them back as `{"type":"thinking"}` with no text or signature, so **every multi-turn record failed with HTTP 400**. The first Bellevue run hit this: 2 of 6 records. The eval harness uses the same `Detective.run`, so **it would have failed the same way**. Fixed, with a regression test. PREREG allows crash fixes.
  - Non-behavioral refactor: `Detective.system`, `Detective.tools` and `Detective.prompt(rec)` are now overridable, so the damage mapper reuses the loop. Prompt text and checks are byte-identical.

- `budget.py` (new): `MeteredClient` + `Ledger`. Before each call it reserves a worst case for that call (request characters / 3 as input tokens + `max_tokens` as output). It refuses the call if the cap could be passed, books the real usage afterwards, and keeps a JSON ledger that one budget can span across runs.
- `damage_mapper.py` (new), `tests/test_damage_mapper.py` (new, 18 tests), `eval/damage_gold.json` (new, hand labels).

## 1. Detective: invented intersections

**Rule** (`detective.py`: `intersection_in_text`).
- An "A & B" query counts as an intersection only if the narrative relates the two streets: both names within 8 words of each other, with a connector between them: at, and, &, near, /, @, or "between … and".
- "Intersection of A and B" reduces to "A and B".
- No ellipsis, semicolon or comma list may sit between the names. A comma is fine before a non-"and" connector ("EVERS ROAD, NEAR POSS ROAD").

**Enforced in three places:**
- the tool marks the candidate `not_acceptable`, so the model sees it;
- `verify_verdict` refuses it with `intersection_not_in_text`;
